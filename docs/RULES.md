# 规则库与法条快照

## 1. 规则库（`backend/rules/adproof_rules.yaml`）

### 顶层结构

```yaml
version: "2026.10.19"
name: 广告合规基础规则库
product_categories: {general: 通用, cosmetics: 美妆个护, food: 普通食品, health_food: 保健食品, ...}
categories: [...]     # 违规分类：标签、默认风险、优先级、法律依据、罚则、默认改写方式
rules: [...]          # 具体规则
disclosures: [...]    # 必要声明（文档级）
```

### 一条规则

```yaml
- id: MED-01                      # 三个大写字母-两位数字
  name: 疾病治疗功能
  category: medical_claims        # 引用 categories 中的 id
  applies_to: [all]               # 或指定商品类目，如 [franchise]
  patterns:                       # 正则，运行在归一化文本上
    - '治疗|治愈|根治|疗效|消炎|抗炎|止痛|止痒'
    - '降(?:血压|血糖|血脂|三高|尿酸)'
  keywords: []                    # 普通关键词（自动转义）
  exceptions: []                  # 例外正则：与命中重叠就不报
  negation: true                  # 命中前几个字内有“不 / 无法 / 没有 / 禁止”等否定词时不报
  unless_sentence: null           # 整句满足该正则时不报（例如写明了“数据来源”）
  law_refs:                       # 在分类依据之外补充的依据
    - {law: advertising_law, article: 18, paragraph: 1, item: 4, when: [health_food]}
  reason: 非医疗类商品宣称疾病治疗功能。
  rewrite:                        # 改写模板（不写则用分类默认）
    strategy: replace             # replace | delete_clause | prefix
    replacements: {消炎: 舒缓}
  examples:
    hit: [喝一个月能降血糖]        # 必须命中
    pass: [本品不能治疗疾病]       # 不能命中
```

### 归一化规则

正则运行在归一化文本上：全角转半角（“，”→“,”，“１００％”→“100%”）、英文小写、去掉空白和零宽字符、去掉夹在两个汉字之间的 `* · ~ _ | - — /` 等符号。宏 `{NB}` 表示一个非断句字符，`{B}` 表示一个断句符号（逗号、句号、问号、感叹号、分号、换行）。命中位置会映射回原文。

### 保存前的检查

控制台“规则库 → YAML 编辑”保存时（也可以只点“校验”）：

1. YAML 语法和字段格式（编号格式、分类是否存在、类目是否存在）；
2. 每个正则都能编译；
3. 每条规则的正例必须命中、反例不能命中；
4. 法条引用能否在本地快照中解析；解析不了的不阻止保存，但会作为“待核对”警告列出，界面上相应依据显示为“待核对”。

前三项不通过则不保存。保存后新的审查记录会带上新的规则库哈希，旧记录保留当时的哈希；每次保存写入审计日志。

## 2. 法条快照（`backend/laws/*.json`）

### 收录范围

| 法规 | 版本 | 收录条款 |
|---|---|---|
| 中华人民共和国广告法 | 2021-04-29 第二次修正，有效 | 第四、八、九、十一、十二、十三、十七、十八、二十四、二十五、二十八条；罚则第五十五、五十七、五十八、五十九条 |
| 中华人民共和国食品安全法 | 2025-09-12 第三次修正，2025-12-01 施行，有效 | 第七十三、七十九条 |
| 化妆品监督管理条例 | 2020-06-16 公布，2021-01-01 施行，有效 | 第四十三条 |

只收录规则库引用到的条款，不是全文。每个文件记录来源（国家法律法规数据库）、该版本在数据库中的记录编号、摘录日期和方法。

### 怎么来的

1. 在国家法律法规数据库（flk.npc.gov.cn）按标题检索，确认当前有效版本（例如《食品安全法》已有 2025 年修正版，不能沿用 2021 年版本）；
2. 在数据库的官方阅读器中打开该版本，逐条摘录规则需要的条款，保留原文的标点（包括中文引号）和“（一）（二）”项号；
3. 用复核脚本对照官方数据库重新检查。

### 复核脚本

```bash
cd backend
python scripts/verify_law_snapshot.py --report ../docs/validation/law-snapshot-verification.json
```

数据库的“命中展示”接口会返回某个法规版本中与检索词相关的官方原文片段，但接口本身是模糊匹配：检索一句编造的话也会返回内容。所以脚本不把“接口有返回”当作证据，而是：

1. 把每条条文（条号 + 各款 + 各项连在一起）切成 16 字的重叠窗口；
2. 每个窗口单独检索，要求窗口**逐字出现**在该版本返回的某个官方片段里；
3. 接口把条文切成固定长度的片段，跨片段边界的窗口找不到时，在未覆盖的位置换用 8～24 字、向前或向后的窗口重试；
4. 最终要求条文的每个字符都被至少一个“逐字找到”的窗口覆盖。例外只有一种：接口在句号处切分时会丢掉句号本身，位于两个已覆盖片段之间的单个“。”无法通过接口验证，报告中单独列为 `boundary_punctuation`，不算缺失（这些句号与官方阅读器中的原文一致）。

脚本只使用 Python 标准库（有 `certifi` 时使用其证书），遇到网站防护返回的 307 会保存 Cookie 后重试，并控制请求频率。它需要联网，不在 CI 中运行。

### 待核对

- 规则可以引用快照以外的条款，系统会显示条款标签和“待核对”，**不展示任何条文内容**；
- 规则可以列出尚未纳入快照的文件（`references`），例如《广告绝对化用语执法指南》，同样只显示标题和“待核对”，备注说明原因；
- 新增法规时，按上面的方法摘录、复核，再在规则中引用。

## 3. 必要声明

文档级检查：脚本全文必须出现其中一个表述。

| 编号 | 适用类目 | 要求 | 依据 |
|---|---|---|---|
| DSC-01 | 保健食品 | 本品不能代替药物 | 《广告法》第十八条第二款；《食品安全法》第七十九条 |
| DSC-02 | 招商加盟 | 投资有风险 / 存在风险 / 风险自担 / 亏损风险 / 经营风险 | 《广告法》第二十五条 |

“零风险”不算风险提示：要求的是上面列出的完整表述。
